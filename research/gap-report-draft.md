# 差距报告草稿：CoGM vs CCFOLIA / 回声岛

状态：草稿（竞品事实已核对，CoGM 实现状态待基线 harness 回填）
依据：`research/competitors.md`（竞品功能清单与来源）、`docs/product.md`（CoGM v1 规划）
日期：2026-10-31

## ① 执行摘要

### 总体定位差异

| 维度 | CCFOLIA | 回声岛 | CoGM |
|---|---|---|---|
| 形态 | 通用在线 TRPG 桌面（盘面 + 聊天 + 骰点） | 通用跑团平台 + 社区 + 创作工具链 | 单团沉浸式文字演出工具 |
| 核心对象 | 房间 / 盘面 / 棋子 | 预设游戏 → 房间 / 舞台 / 频道 | 模组 → 团 / 场景 / 立绘 |
| 规则策略 | BCDice 200+ 系统，插件式广度 | 7 套内置规则 + 可编程指令/物品，深度定制 | 只做 CoC 7e，服务端判定 |
| 演出策略 | 手工摆面板、cut-in、场景预设 | 沙盒 UI + 场景动画 + 转场 + 遮罩 + 触发器 | 固定演出公式：背景 + 立绘 + 对话框 |
| 叙事控制 | 无（全员自由发言） | 无（场内/场外只是标记） | 演绎放行队列 + 阶段闸门 |
| 状态管理 | 自由 label 数值，无规则语义 | 规则绑定 + 公式派生 + 自动写回 | 团内状态（HP/MP/SAN/标记/成长） |
| 学习成本 | 低（会用聊天框就能玩） | 高（沙盒/指令/模板需要理解概念） | 目标：低（玩家零配置） |

### 一句话结论

**两家竞品都没有解决「叙事时序」和「状态闭环」这两个问题：CCFOLIA 强在零门槛与规则广度，回声岛强在演出与自动化，但都不控制「谁的话在什么时候上屏」；CoGM 的差异化必须压在「演绎放行队列 + CoC 7e 服务端权威判定 + 立绘/音频同步」这条主线上，其余功能按「不破坏沉浸感」的标准裁剪。**

### 三条必须先承认的事实

1. 单看「功能数量」，CoGM v1 大致相当于 CCFOLIA 的一个子集 + 回声岛的骰点/状态子集；正面拼广度没有胜算。
2. 单看「演出表现力」，CoGM v1 低于回声岛（无场景动画、无遮罩、无转场特效、无 TTS、无回放），需要明确「克制的舞台感」是否是设计意图，否则会被用户按回声岛的标准评价。
3. 单看「跑团核心闭环」（检定 → 扣状态 → 成长 → 复盘），CoGM 的规划已经比两家都完整：唯一缺的是复盘/日志这一段。

## ③ 竞品独家亮点（CoGM 完全没有对应规划）

### CCFOLIA 独家

1. **BCDice 全量规则与原创随机表**：建房即选规则，200+ 系统；`/roll-table` 可现场定义表。CoGM 只做 CoC 7e，此处是明确放弃项，不是负债。
2. **卡牌牌堆**：建堆、抽 1/10/任意张、背面抽、回收、合并、标准扑克。CoGM 无对应规划，CoC 7e 也不需要。
3. **面板即交互对象**：点击动作（点图即掷骰/切场景/开 PDF）、翻面私看、仅自己以外可见。CoGM 的「情报」只覆盖信息发放，没有「场景里可点的物件」这一层。
4. **双轨音量 + 文件级音源设置**：文件音量影响所有人、个人音量只影响自己；同一房间两路 BGM 同时播。
5. **差分标签驱动**：把 `成功/失敗/致命的失敗` 设为差分标签，骰点结束自动换表情，零配置。
6. **零成本「场景预设」运维**：场景覆盖保存 + 可只应用部分要素（不带 BGM / 不带文本）+ 场景列表拖拽排序。
7. **棋子跨房间复制**（Ctrl+C/V，含属性与立绘）。
8. **游客免注册进房**（CoGM 已有对应设计，属于对齐项而非差距）。

### 回声岛独家

1. **自动录制 + 可编辑回放**：房间首次发言即开录，记录一切操作；结团归档为可交互 Replay，可在「留声机」位置回改，导出 1080p 视频。
2. **LogBook 排版**：把聊天记录排成印刷品（封面/目录/插页/样式规则/HTML 模板），导出 PDF、生成免登录阅读链接、社区模板复用。
3. **沙盒 UI 引擎**：节点 + 变量 + 条件显示 + 自我复制（表格循环）+ 嵌套 + 代码节点，可发布社区并版本化。这是「演出上限」的来源，也是学习成本的来源。
4. **可编程规则层**：自定义指令（QuickJS，可在房间内改参数覆盖）、物品规则引擎（条件/动作/标签链/AOE/试验台）、规则数据表与审核组。
5. **TTS 角色朗读**：700+ 音色、自建音色、多情绪，游戏与回放都能读。
6. **触发器**：关键词/正则、检定结果、属性阈值 → 音效/瞬时遮罩，带冷却与次数上限。
7. **频道即舞台**：每频道独立场景/音乐/立绘/记录；实况频道按玩家在场时间裁剪可见消息。
8. **真实货币交易市场**：模组/预设游戏/素材集可上架，卖家自配收款，平台分账。
9. **AI 辅助链路**：站内 AI 生成沙盒代码/物品 YAML/车卡模板；深度图转 3D 视差；AI 音色设计；AIGC 标识。
10. **社区基础设施**：论坛分区、招募、工单（含权利人通知）、成就头衔、公开 NPC 库、公开知识库。

**判断**：以上 20 项里，只有 4 项直接服务于「一场 CoC 团的当场体验」——cut-in/触发器、差分自动切换（CCFOLIA 侧）、回放（回声岛侧，且是结团后）、TTS（回声岛侧，可选）。其余是平台化能力，与 CoGM 的 v1 定位无关。

## ④ 优先级建议

排序原则：① 是否影响「一场团能不能跑完」；② 是否强化「沉浸式文字演出」的差异化；③ 是否能以现有架构低成本落地。不按竞品功能数量排。

### P0 — 不做就不能开团（v1 门槛）

1. **演绎放行队列闭环**
   - 服务端队列 + 顺序调整 + 丢弃静默；玩家端无「审核中」状态。
   - 表情切换必须与消息同一事务提交后广播，避免「脸变了话没上」。
   - OB 发言全量过审。
   - 验收：GM 端队列延迟 < 200ms；丢弃后玩家侧无任何新增 UI 或提示。
2. **CoC 7e 判定闭环**
   - 服务端持有目标值；六档判定；0–2 奖惩骰；难度档；暗骰。
   - SAN 检定：自动掷损失、扣减、广播、≥5 提示。
   - 成长标记：成功即记，结团可导出。
   - 验收：前端只发意图，篡改请求无法改变结果；重连后状态一致。
3. **场景切换 + 立绘演出**
   - 场景 = 背景 + 元数据；切换全员同步带转场；中途加入从快照恢复。
   - 立绘：多差分、GM 全场切换、玩家本地预览、发言带表情。
   - 验收：10 人同时切场景无撕裂；新加入者 3 秒内看到正确场景 + 当前立绘。
4. **音频同步**
   - BGM 通道：GM 权威时间轴，广播「曲目 + 起播时间戳 + 播放位置」，客户端按时钟校准；中途加入从当前进度续播。
   - SE 通道：广播即播，不去重不错序。
   - 本地静音不影响他人。
   - 验收：两次切歌后两端进度差 < 300ms；断线重连不出现双播。

### P1 — 决定「像不像一个成品」（v1 内应完成）

5. **鉴定请求**（GM 指定角色/技能/难度/奖惩骰 → 玩家一键掷）——两家都没有，CoGM 独占；实现成本低于它的体验收益。
6. **角色级快捷片段**（技能检定 / SAN 检定 / 常用台词 / 表情），等价于 chat palette，但绑定到角色与规则。
7. **房间口令 + 邀请链接 + 等待态**：补足入场摩擦与链接外泄风险。
8. **消息编辑 / 撤回**：跑团中写错字是高频事故；撤回要留痕。
9. **日志结构化落库**：消息、骰点、场景切换、表情切换、情报发放全部事件化存储。即使 v1 不导出，也必须现在决定 schema，否则 Replay 永远补不上。
10. **移动端可用**：单列聊天 + 全屏场景切换、软键盘不遮输入框、横屏提示。不做 PWA/APK。

### P2 — 强化差异化（v1.1）

11. **轻量 cut-in**：一张图 + 一段音，可由「骰点结果等级」或「关键词」触发；不做遮罩层与通用触发器引擎。
12. **对抗检定 + 疯狂/恐惧表**：CoC 7e 带团真实高频；表可用静态数据实现，不必接 BCDice。
13. **结团一键成长**：按成长标记批量掷 1d100 与 1d10，写回人物卡（跨团静态值）。
14. **先攻表**：排序 + 当前行动者 + 回合数，不做 AOE/光照/迷雾。
15. **模组打包导入导出**：让 GM 能把一套场景/立绘/音乐/情报带走。

### P3 — 明确不做（写进文档，避免反复讨论）

- 地图棋子、迷雾、光照、测距、AOE 范围。
- 卡牌牌堆、计时器、3D 骰动画、骰子皮肤。
- 沙盒 UI、代码节点、自定义脚本引擎、物品规则引擎。
- TTS 朗读、AI 生成内容、素材市场、社区论坛。
- 多规则支持（保留架构扩展点即可）。

### 工程侧三条硬约束（与竞品对照得出）

1. **可见性判定必须在 repository/服务层**：CCFOLIA 官方自己写明秘匿「不是严格隐藏，房主可导出全日志查看」，回声岛的线索粒度是频道而非个人。CoGM 的秘密情报一旦做成「广播后前端隐藏」，就失去唯一可信的卖点。
2. **实时操作先提交事务再广播**：竞品都存在「状态与画面不同步」的运维问题（回声岛专门做了 `sync-state-mismatch`、`replay-write-anomaly` 提示与自动修复）。CoGM 的既有约定（WebSocket 操作先提交事务再广播）应扩展到场景切换、表情切换、情报发放。
3. **事件溯源优先级高于导出格式**：回声岛能做出 Replay/排版/视频，前提是「留声机记录一切操作」；CCFOLIA 只有静态日志，所以永远做不出回放。CoGM 现在多花一天设计事件表，未来省一个月。

### 一句话优先级

**先把「队列 + 判定 + 立绘 + 音频」四条主线做到零故障，再补「鉴定请求、快捷片段、口令入场、日志落库」；其余竞品功能一律不做，直到有真实团反馈证明缺口。**
