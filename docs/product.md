# CoGM（主持人的呼唤）产品需求 — v1

网页跑团工具，参考 CCFolia 的 UI 与功能，目标是文字游戏式的沉浸体验：场景背景图 + 人物立绘 + 对话框。v1 专注适配 CoC 第 7 版规则，架构上为未来支持多规则留出扩展点。

## 角色与进入方式

- **主持人（GM）**：密码登录，拥有全部管理与控场能力。
- **玩家（PL）**：无需注册，匿名进入网站，从 GM 预设的 PC 列表中认领角色，或选择 OB（观战）位。
- 人物卡审核流程发生在站外：玩家通过社交媒体将人物卡 Excel 发给 GM，GM 审卡后在后台导入。

## 模组与团

- **模组（Module）**：资源容器。一个模组下管理它的场景（背景图）、人物（NPC）、音乐等。
- **团（Session）**：实际游玩单位。每个团对应一个模组；创建团时指定参与的 PC。人物可以属于多个团。
- **团状态**（GM 控制）：`等待开始` → `准备中` → `进行中` → `已结团`。
- **团内阶段**（仅"进行中"时，GM 控制）：
  | 阶段 | 规则 |
  |---|---|
  | 自由讨论 | 所有人可发言，所有消息一律记为场外（OOC） |
  | 演绎时间 | 仅允许演绎发言，经 GM 放行后呈现（见下）；禁止场外发言 |
  | 强制 CG | 所有人禁言，GM 单方面推进演出 |
  | 自由演绎 | 玩家可自由发言，每条消息自选"场外"或"角色扮演"，角色扮演消息同样经 GM 放行 |
- 发言权限的判定必须由服务端执行，前端仅做展示与输入禁用。

### 演绎发言的隐式审核

- 所有演绎性质（角色扮演）的发言，发送后先进入 GM 的**待呈现队列**，GM 放行后才呈现到场景画面——目的是让画面干净、叙事有序。
- 该流程对玩家**完全无感**：玩家只是按下发送键，界面上不存在"申请"概念，也不展示审核状态。
- GM 在控制台看到实时队列，可调整放行顺序，也可丢弃某条（玩家侧同样无提示）。
- 演绎发言可携带发言者自己人物的表情切换，放行时随消息同步生效。
- PC 玩家的场外（OOC）消息不经队列，即时呈现于聊天区。
- **OB 例外**：OB 位置的所有发言（一律为场外性质）都必须经 GM 同意后才发送到公屏。

## 场景管理

- 场景 = 背景图 + 元数据，归属于模组。
- GM 在团进行中切换当前场景，所有客户端同步切换（带转场效果）。

## 人物管理

- 人物属性：立绘（多张，对应表情/状态：默认、生气、惊讶、受伤等）、姓名、CoC 7e 数值卡。
- 支持 CoC 人物卡 Excel 一键导入数值。
- GM 可在团内实时切换任意人物的当前表情/状态立绘，全员同步。
- 玩家可在演绎发言中切换**自己人物**的表情（随该条发言被 GM 放行时一并生效），并可随时本地预览自己人物各表情/状态对应的立绘。
- 区分 PC（玩家认领）与 NPC（GM 控制）。

## 音乐管理与播放（GM 控制）

- 音乐文件归属模组，GM 后台上传管理。
- 团进行中，**播放完全由 GM 控制**：选曲、播放/暂停、音量、循环、淡入淡出、切歌。玩家端只是受控的同步播放器（本地可静音）。
- 分两类通道：
  - **BGM**：循环长音频，需要全员进度同步，中途加入者要能从当前进度继续。
  - **SE（音效）**：一次性短音频，广播即播，不需要进度同步。
- 浏览器自动播放限制：玩家进团的点击交互即作为音频解锁手势。

## 情报管理（GM 发放）

- **情报（线索/Handout）**归属模组，GM 后台预先准备，条目包含：标题、文字内容、可选图片附件（地图、关键道具、手记等）。
- 团进行中由 GM 发放，两种可见范围：
  - **公开情报**：发给全体（含 OB）。
  - **秘密情报**：仅发给指定的一个或多个 PC，其余人（含 OB）不可见、也感知不到发放行为。
- 已发放的秘密情报可**追加**发放对象（如玩家之间共享线索后 GM 公开化）；v1 不支持撤回。
- 玩家端收到情报时有醒目提示并弹出展示，之后可在"情报"面板随时回看自己已获得的全部情报。
- 情报可见性判定为服务端权威：秘密情报只推送给可见者，禁止广播全员后由前端隐藏。
- 中途加入、断线重连的玩家能收到对其可见的全部已发放情报。

## 在线管理与黑名单

- GM 可查看当前在线玩家（含所选 PC/OB 身份）。
- GM 可踢出玩家；可将玩家的浏览器指纹拉入黑名单，支持设定时长（含永久）。
- 指纹为尽力而为的标识，不假设其绝对可靠。

## UI

- 简洁优雅。全站统一深色主题（以墨色为底），玩家沉浸视图与 GM 后台共用同一套语义设计 token。
