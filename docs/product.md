# CoGM（主持人的呼唤）产品需求

网页跑团工具，参考 CCFolia 的 UI 与功能，目标是文字游戏式的沉浸体验：场景背景图 + 人物立绘 + 对话框。支持 CoC 第 7 版与 D&D 第五版（2024 规则）。账号、所有权、人物版本与模板见 `docs/redesign-multi-ruleset-accounts.md`。

## 账号与进入方式

- **管理员（admin）**：唯一能创建/禁用/恢复账号、管理实例设置与主题包的角色。不查看 GM 模组与团内容，不控场，不查看 PL 人物库。
- **主持人（GM）**：用户名 + 密码登录，管理自己的模组、NPC、预建 PC、团与模板，拥有自己团内的控场能力。
- **玩家（PL）**：用户名 + 密码登录，拥有独立工作台与人物库，可独立建卡、通过 GM 链接提交审核、认领自己的人物参与团。
- **匿名 OB**：仍可匿名进入，只能选择 OB（观战）位；PC 席位必须由 PL 账号持有。
- 三类账号完全分离，无能力继承、不可互相转换；无公开注册，账号由 admin 创建；用户可改自己密码，admin 可重置。
- 每种账号同一时刻只有一个活动浏览器会话：新浏览器登录顶替旧会话并断开其连接；同浏览器多标签页共享会话。匿名 OB 不受此限制。
- **单座位**：每位参与者（账号或匿名玩家）在同一团内最多持有一个活跃座位；认领新座位会替换原座位，原窗口收到「座位已被接管」通知并停止同步（不支持一人多座）。
- 人物审核通过链接完成：GM 生成模组或团链接，PL 登录后提交新建人物或已有任务，GM 在后台审核。链接默认 7 天有效、可撤销，只用于提交/选择，不批准、不分配席位、不建账号。

## 模组与团

- **多规则**：模组、团、人物、模板各自绑定单一规则，创建时必须显式选择，创建后不可切换。规则选择器列出服务端已注册且与核心兼容的规则（`coc7e`、`dnd5r`），不提供默认规则。
- **模组（Module）**：资源容器，归属创建它的 GM。一个模组下管理它的场景（背景图）、人物（NPC）、音乐、情报、主题等。
- **团（Session）**：实际游玩单位，归属创建它的 GM 并继承模组规则。创建团时指定参与的 PC 并可选填团名（留空时界面回退显示模组名，GM 可在团管理中随时重命名）。人物可以属于多个团，不设角色占用锁。
- 团实时引用模组的场景、音乐、情报；GM 新增资源后，现有团立即可用。
- **模板（Template）**：独立的、可编辑的模组快照。模板包含场景、音乐、情报、团设置与 NPC 副本，不包含 PL 主人物、账号、席位、成长与运行记录。模板与源模组、已实例化模组均不自动同步；支持“当前内容 + 显式保存的历史版本”，可直接从模板创建模组，或一次性“快速开团”创建独立模组与等待开始的团。
- **所有权隔离**：GM 只能访问自己的模组、人物、团与模板；管理员不查看这些内容；PL 只能访问自己的人物与参与的团。他人资源与不存在资源统一表现为 404。
- **团状态**（GM 控制）：`等待开始` → `准备中` → `进行中` → `已结团`。
- **团内阶段**（仅"进行中"时，GM 控制）：
  | 阶段     | 规则                                                                       |
  | -------- | -------------------------------------------------------------------------- |
  | 自由讨论 | 所有人可发言，所有消息一律记为场外（OOC）                                  |
  | 演绎时间 | 仅允许演绎发言，经 GM 放行后呈现（见下）；禁止场外发言                     |
  | 强制 CG  | 所有人禁言，GM 单方面推进演出                                              |
  | 自由演绎 | 玩家可自由发言，每条消息自选"场外"或"角色扮演"，角色扮演消息同样经 GM 放行 |
- 发言权限的判定必须由服务端执行，前端仅做展示与输入禁用。

### 演绎发言的隐式审核

- 所有演绎性质（角色扮演）的发言，发送后先进入 GM 的**待呈现队列**，GM 放行后才呈现到场景画面——目的是让画面干净、叙事有序。
- 玩家侧会看到自己发言的**待审查**状态；放行后才进入公共聊天时间线。
- GM 在控制台看到实时队列，可调整放行顺序，也可拒绝某条并填写拒绝理由；玩家会看到「未通过」及理由。
- 演绎发言可携带发言者自己人物的表情切换，放行时随消息同步生效。
- PC 玩家的场外（OOC）消息不经队列，即时呈现于聊天区。
- **OB 例外**：OB 位置的所有发言（一律为场外性质）都必须经 GM 同意后才发送到公屏。

## 场景管理

- 场景 = 背景图 + 元数据，归属于模组。
- GM 在团进行中切换当前场景，所有客户端同步切换（带转场效果）。

## 人物管理

### 人物模型与所有权

- 人物 = 通用资料（姓名、简介/背景）+ 独立表情列表 + 规则专属人物卡。表情可增删、命名、排序、设默认；内置表情预设仅作为建卡初始模板。
- 规则专属的结构化背景（如 CoC 7e 的背景 8 格、关键链接与同伴关系）在「完整人物卡」与「资料与立绘」均以结构化 UI 呈现，不再自动拼接覆盖纯文本摘要；人物的「详细背景描述」独立保存，供玩家自由撰写生平与补充设定。
- 人物属性包含：立绘（多张，对应表情/状态：默认、生气、惊讶、受伤等）、姓名、背景、数值卡。
- 支持 CoC 人物卡 Excel 一键导入数值。
- PL 拥有独立人物库，可独立建卡（只能创建 PC）。GM 可预建 PC 并分配给 PL，分配后人物归 PL；NPC 始终归 GM。PL 人物不能转为 NPC，需要时由 GM 建独立副本。
- 人物提交审核通过链接完成：模组链接审核通过后建立模组-人物关联；团链接审核通过后进入该团可用 PC 列表，并按审核版本初始化团内状态。链接只用于提交/选择，不批准、不分配席位、不建账号。

### GM 人物库（`/gm/characters`）

- 以**规则**为一级单位浏览：GM 一次只在一个规则内工作，规则选择器显示各规则人数（有人物的规则按人数排前，可搜索），并记住上次使用的规则；新建人物归入当前规则。
- 规则内按 类型（PC/NPC）、归属（我创建的/玩家持有）、模组（含“未归入模组”）组合筛选，并支持按名字搜索、按最近更新/名称/有立绘优先排序；各筛选项显示分面计数（按其余已选条件计算）。
- 列表与立绘墙只显示规则无关字段（立绘、姓名、类型、所属模组、归属、更新时间）；规则数值只在详情检视器中，由规则组件提供的摘要呈现。
- 人物库包含 GM 自有人物，以及经审核关联到其模组或进入其团内的玩家人物；玩家人物只读（查看人物卡、可再关联到同规则的其他模组，不可删除或改立绘）。
- 为支撑上百人规模，列表走轻量接口 `GET /api/v1/gm/characters/library`（不含人物卡 JSON，服务端过滤/排序/分页与分面计数），筛选状态保存在 URL。
- 访问隔离：GM 只能读取自有人物，或与其模组关联、在其团内、或提交给其审核的玩家人物；删除与修改仅限自有人物；关联模组只接受上述可见人物。他人资源统一 404。

### 车卡属性生成（CoC 7e）

- 只适用于 CoC 7e，其他规则不提供。生成方式由 GM 在生成提交链接时设定，掷骰全部在服务端完成：
  - **手填**（默认）：玩家自行填写九项属性，页面不提供掷骰。PL 不经链接、在人物库独立建卡时也只能手填。
  - **天命 N**（N 为 1–10，默认 5）：玩家打开链接后点一次“天命骰”，服务端一次掷出 N 套完整属性（STR/CON/DEX/APP/POW/幸运 3D6×5，SIZ/INT/EDU (2D6+6)×5），每套显示 HP、DB 与不含/含幸运总和。玩家任选其一，属性自动填入人物卡。GM 可勾选“允许改购点”并设置转购点总数（300–600，默认 460）：玩家对天命结果不满意时可改用该点数分配八项属性；改购点的幸运随天命骰一并由服务端预掷，转换前不显示，转换后不可重掷。
  - **购点 + 骰幸运**（总点数 300–600，默认 460）：玩家把总点数分配到 STR/CON/SIZ/DEX/APP/INT/POW/EDU 八项（每项建议 15–90，页面实时显示已分配与剩余），幸运由服务端掷一次 3D6×5。
- 每位玩家在每条链接上只能掷一次；刷新、换设备或重复点击都返回同一结果。设定了生成方式的链接，新建人物必须先完成掷骰与选定才能提交。
- 选定可在提交人物前改选：天命各套之间、以及开放了改购点的链接中天命与购点之间可来回切换；提交人物时服务端锁定选择，审核比对使用锁定的结果，之后不可再改选。
- 15–19 岁调查员的“幸运掷两次取较高”：服务端掷骰时一并掷出第二次幸运，玩家填入时按年龄取较高值。
- 选定后人物卡属性仍可修改（例如年龄带来的属性扣减与 EDU 增强）。GM 在提交审核页看到提交者的掷骰记录，并与提交版本的属性逐项比对、高亮差异，由 GM 判断是否合理。

### 版本、审核与成长

- 审核绑定人物的规则卡版本：改动规则数值、技能或终生字段后需要重新审核；仅改背景、简介、立绘无需重审，GM 始终能看到最新资料。
- GM 可修改规则声明的“终生字段”（CoC 为九项属性），必须记录团、GM、旧值、新值、时间与可选原因，并向 PL 展示。
- 人物版本、成长记录、GM 修改审计均为追加式历史，不提供用户删除或编辑。能查看某人物完整成长与修改历史（含其他团记录），但不提供全站 PL 角色库搜索目录。
- 结团时由 GM 审核确认成长，按技能增量写入主卡并追加成长记录；历史团保留当时版本，不被回写。
- 同一人物可同时用于多个未结团，每团使用自己的入团快照与独立团内状态。主卡变更不会自动进入团内，需由 GM 预览差异并显式同步。同步只更新所选字段，由各规则按新卡重新计算团内上限。
- 并行修改禁止整卡静默覆盖：增量成长可累计，冲突修改须基于最新版本重新确认。

### 团内展示

- GM 可在团内实时切换任意人物的当前表情/状态立绘，全员同步。
- 在舞台编排中选定的上台角色表情纳入草稿，随「同步放映」或「实时同步」应用。机位快照保存排布，借看背景与模拟对话供本地验看。
- GM 工作台顶栏提供统一的「舞台」编排与玩家视角预览入口，在 1:1 玩家视角与模组主题画布内自由编排立绘上下台（最多 12 人，支持空台）、X/Y 自由位置拖拽（带智能吸附线）、独立缩放、水平镜像翻转、前后层级、一键快捷排版与「聚焦发言人」开关（聚焦时仅压暗非发言人，尊重 GM 手动前后层级）；支持按「桌面（含聊天）/ 桌面（全屏）/ 手机竖屏」切换试看，并可在本地借看本模组其他场景背景、使用模拟对话框检查构图，不改动线上场景与时间线。编排默认处于本地草稿态（关闭弹窗自动保留草稿并在顶栏提示），确认效果后点「同步放映」才推送全团，亦提供可选「实时同步」开关；支持在「等待开始」状态提前预摆台，并可在本团内保存命名「机位快照」（最多 16 个）随时一键载入预览再放映。主持人背景舞台仍复用玩家桌面舞台的立绘排布；已结团时入口自动以只读玩家视角预览打开；预览中的 NPC 状态使用服务端玩家公开视图。未手工编排前自动兼容展示 PC，编排后严格以 GM 显式在台名单为准，新加 NPC、切表情或以 NPC 发言不自动插队。
- 舞台编排默认显示「主持人视角」，复用 GM 控制台的舞台和可用尺寸。预览缩入编排画布时等比缩放，开启名牌状态也不会移动立绘。玩家视角仍可切换查看。
- 玩家可在演绎发言中切换**自己人物**的表情（随该条发言被 GM 放行时一并生效），并可随时本地预览自己人物各表情/状态对应的立绘。
- 区分 PC（玩家认领）与 NPC（GM 控制）。
- GM 可在团进行中把自有 NPC 加入本团（自动关联当前模组），也可把 NPC 移出本团；移除只影响本团，不删除人物，之后可重新加入。
- GM 的发言可选择身份：主持人或本团任一 NPC。以 NPC 身份发言即时呈现，并可同时切换该 NPC 的表情立绘（随发言同步全团）；聊天记录与舞台对话在发言人附近显示该条发言使用的表情，不再只显示独立的表情切换记录。
- 人物卡可见性由团级设置「公开队友人物卡」控制（默认开启）：开启时所有参与者（PC 玩家与 OB）都能查看全部 PC 的人物卡摘要（属性/技能）；关闭时每位玩家只能查看自己认领的 PC。NPC 人物卡始终仅 GM 可见。
- 该设置由 GM 在控制台切换，判定在服务端完成；设置变更即时同步到所有连接。
- PL 通过明确的团链接进入且只有一个可认领的已审核 PC 时，登录后自动认领；多个则显示选择页。普通登录只进入 PL 工作台。

## 掷骰与鉴定

所有随机数由服务端生成并判定，前端只提交意图（表达式/技能名）、只渲染结果。骰点消息不经演绎队列，即时呈现于聊天区（暗骰除外）。

实时收到公开 `dice:rolled` / `check:resolved` 事件时，玩家沉浸视图与 GM 控制台直接在网页舞台上层播放一次 3D 骰子翻滚动画：全屏透明叠层承载 WebGL 骰子，不使用弹窗或小窗；先随机翻滚，再按定向四元数落到服务端已给出的点数。动画只表现已定结果，不产生随机数、不决定检定判级；暗骰不播放动画，快照、历史回看与历史分页也不重播动画。

### 普通掷骰

- 支持骰点表达式 `XdY±Z`（如 `1d100`、`3d6+2`），可附一句说明文字。
- 输入方式：玩家或 GM 通过骰点面板选择骰子、修正值并填写可选说明；前端提交结构化骰点意图。v1 不解析聊天文本中的骰点命令。
- 普通掷骰不需要主持人同意；服务端即时生成结果并广播。

### 技能鉴定（CoC 7e）

- 鉴定读取该角色人物卡上的技能/属性数值作为目标值（目标值由服务端从库中读取，前端不传数值），服务端掷 1d100 并判级：

  | 结果     | 条件                            |
  | -------- | ------------------------------- |
  | 大成功   | 掷出 1                          |
  | 极难成功 | ≤ 目标值/5                      |
  | 困难成功 | ≤ 目标值/2                      |
  | 常规成功 | ≤ 目标值                        |
  | 失败     | > 目标值                        |
  | 大失败   | 掷出 100；目标值 < 50 时 96–100 |

- 支持 0–2 个奖励骰/惩罚骰（多掷十位骰取较优/较劣）；GM 可指定难度等级（常规/困难/极难），按对应阈值判定成败。
- 发起方式：
  - 玩家点击自己人物卡上的技能/属性直接鉴定，前端提交人物与技能标识；聊天文本不作为鉴定入口。
  - GM 可对任意角色（含 NPC）发起鉴定；也可向指定 PC 发送**鉴定请求**（指明技能、难度、奖惩骰），玩家端弹出一键掷骰。
- **暗骰**：GM 自己的掷骰/鉴定可标记为暗骰，结果仅 GM 可见；鉴定请求也可标记为暗骰——玩家掷出后只看到"已掷出"，结果与等级仅 GM 可见（心理学、侦查等守密人暗骰场景）。
- 鉴定达到常规成功及以上时，自动为该技能打**成长标记**（记入团内状态）。对抗鉴定与成长鉴定 v1 不自动化，由 GM 线下裁决。

### 理智检定（CoC 7e）

- 对角色**当前 SAN**（团内状态值）掷 1d100，GM 发起时附损失表达式 `成功损失/失败损失`（如 `1/1d6`）。
- 判定后服务端自动掷损失骰、扣减团内 SAN 并广播；单次损失 ≥ 5 时提示 GM 考虑临时疯狂（疯狂状态由 GM 手动标记，不自动挂）。

### D20 鉴定与遭遇（D&D 第五版，2024）

- 角色卡记录六项最终属性、等级、职业、种族和背景，按 1–20 级推导熟练加值、技能、豁免、生命值、AC 与施法数值。GM 可以用里程碑决定升级，也可以记录 XP。GM 同步新卡后，当前 HP 仅在超过新上限时下调。生命骰、法术位和仍存在的资源按新上限扣除已消耗次数，最低为 0。新增资源从满额开始。
- 服务端按人物卡、鉴定种类和优势或劣势掷 D20。可用 DC 或 AC 判断成败，也可以仅掷出总值。GM 可向指定 PC 发起公开或暗骰鉴定请求。玩家只可操作自己认领的人物。
- 武器攻击可以指定遭遇中的目标。服务端读取目标 AC、计算暴击伤害并更新团内状态。结果中不下发目标 AC，NPC 的 HP 默认仅 GM 可见。
- GM 管理先攻排列、轮次和休整，并裁定反应、法术效果和位置。内置目录收录 SRD 5.2.1 的职业、起源、装备、法术元数据与部分可用的生物预设。见 [目录与规则覆盖](dnd5r-srd.md)。

### 阶段规则

- 玩家自主掷骰视同场外发言：自由讨论/自由演绎阶段允许，演绎时间/强制 CG 阶段禁止（服务端裁决）。
- 响应 GM 的鉴定请求不受阶段限制；GM 在任何阶段都可掷骰。

## 角色团内状态

- 人物卡是跨团的静态数值；**团内状态**归属"团 × 角色"，同一人物在不同团的状态互不影响。
- **CoC 7e 状态内容**：
  - **数值条**：HP / MP / SAN 的当前值与上限。进团时从人物卡推算初始化（HP 上限 =（体质+体型）/10、MP 上限 = 意志/5、SAN 初始 = 意志），GM 可随时修改当前值与上限。
  - **状态标记**：预置标记（重伤、濒死、昏迷、临时疯狂、不定性疯狂、死亡）+ 自定义文本标签。
  - **成长标记**：本团内鉴定成功过的技能清单，结团后供 GM 处理成长。
- CoC 7e 的状态变更由 GM 手动编辑、理智检定自动扣减或鉴定后的成长标记产生。
- 自动提示（只提示，不自动挂状态）：单次伤害 ≥ HP 上限一半 → 提示重伤；HP 归 0 → 提示濒死/死亡；单次 SAN 损失 ≥ 5 → 提示临时疯狂。
- **D&D 第五版（2024）状态内容**：HP、临时 HP、状态与力竭、死亡豁免、生命骰、法术位和职业或自定义资源。攻击和死亡豁免可自动变更状态。GM 负责伤害、治疗、状态标记和休整，玩家可花费自己的法术位和资源。
- 可见性：PC 的状态对 GM 与所有 PC 玩家可见。NPC 状态默认仅 GM 可见。GM 可按团内 NPC 分别公开规则允许的字段（CoC 7e 的 HP、MP、SAN、状态标记，D&D 的 HP、临时 HP、状态与力竭）。NPC 人物卡始终仅 GM 可见。
- 团级设置「OB 可见 PC 数值」（默认开启，保持既有行为）关闭后，OB 收到的 PC 团内状态为 null，且不再接收任何 PC 的 `state:changed` 事件；过滤按连接在服务端完成。PC 与 PC 之间仍互相可见。
- 状态变更实时同步；断线重连与中途加入从快照恢复当前状态，快照按当前可见性设置裁剪。

## 音乐管理与播放（GM 控制）

- **音乐库页（`/gm/music`）**：GM 备团时管理曲目的唯一入口，上传、平台搜索/单曲链接、歌单导入都在此页完成，不必再跳到模组页。左栏（移动端为单行选择器）按模组切换，另有“全部曲目”跨模组视图；模组再多也只是一个可滚动、超过 6 个时可搜索的列表，并记住上次使用的模组。曲目按 BGM / SE 分成两“幕”，各自说明行为（BGM 循环、一次只放一首；SE 点一下播一次），可按名称/艺术家/专辑搜索、按类型筛选、按最近添加/名称/时长排序；“全部曲目”中每幕内按模组分组。
- 试听只在 GM 本机播放，不广播给任何团：同一时间只放一首，BGM 循环、SE 播一次，平台曲目走服务端代理流；试听条贴在列表底部（可拖动进度、调节音量、随时停止），切换模组或筛选时不会中断。行内可重命名、改 BGM/SE 类型、打开平台官方页、删除；可多选后批量改类型或删除（逐首执行，部分失败会明确提示）。删除曲目前需确认，正在使用该曲目的团会停止播放。
- 把音频文件直接拖进某个模组的列表即可进入上传队列：队列里可逐个改名、改类型，30 秒以内的默认记为 SE；逐个上传，失败的留在队列里可重试。“全部曲目”视图只读，需先选一个模组才能添加。
- 曲目归属模组并供现有团实时引用，来源为本地上传、网易云音乐或 QQ 音乐；平台曲目通过歌曲 ID 或官方歌曲分享页搜索、解析并添加，和上传曲目一样进入模板当前内容、历史版本与实例化副本。
- 平台曲目只支持无需登录、购买、VIP 或额外版权权限即可由官方公开网页/接口访问的音频。系统不使用第三方音乐镜像，不绕过付费、登录、VIP、地区或版权限制；解析或播放时不可用的歌曲返回明确错误，不显示为播放成功。
- 平台曲目保存官方歌曲 ID、官方分享页与元数据，不保存会过期的音频直链。播放时由服务端重新向官方解析并代理音频；平台可用性可能随版权与地区变化，添加时探测成功不保证永久可用。
- GM 可在声音面板粘贴网易云音乐或 QQ 音乐的公开歌单 ID/官方歌单页，按 `nextOffset` 连续加载（每页最多 50 首）并跨页保留勾选。歌单不是新的持久化资源，不持续同步或自动刷新；若宣称整份导入，必须加载至 `nextOffset=null` 并选择全部歌曲；只导入当前已加载并勾选的歌曲时，必须明确标示实际导入范围，不能只导入第一页却宣称完整。客户端按模组、平台和官方歌曲 ID 去重后逐首添加，展示真实进度与部分失败。
- 歌单解析只提供公开元数据和 `unknown` 可播性，不逐首探测音频。每首歌曲仍通过现有单曲添加流程验证匿名公开可播性，成功后成为普通模组曲目并复用模板、播放与 WS 同步；不可播或单首失败不伪装成功，也不回滚其他已成功的曲目。
- 团进行中，**播放完全由 GM 控制**：选曲、播放/暂停、音量、循环、淡入淡出、切歌。玩家端只是受控的同步播放器（本地可静音）。
- BGM 播放模式为「列表循环」「单曲循环」「随机播放」「播完停止」，通过播放器旁的图标文字按钮选择。列表循环按模组未删除的背景音乐创建时间、ID 顺序播放并首尾循环；随机播放在有多首时避开当前曲目；仅一首时继续重播，无可用曲目时停止。手动上一首/下一首由服务端选曲，随机模式下两者都随机选择另一首，其余模式按曲库顺序切换。
- 单曲循环由同步播放器重复当前音频；其他模式在 GM 播放器结束或重连发现曲末时回报，服务端校验权威版本、团状态与结束进度后决定切歌或停止并向全团广播。关闭声音面板不影响该回报；GM 离开控制台或断线期间不自动选下一首，重新连接后继续处理。玩家不发送结束指令，不自行选歌。切换模式保留当前播放进度，旧循环开关迁移为单曲循环或播完停止。
- 分两类通道：
  - **BGM**：循环长音频，需要全员进度同步，中途加入者要能从当前进度继续。
  - **SE（音效）**：一次性短音频，广播即播，不需要进度同步。
- 浏览器自动播放限制：玩家进团的点击交互即作为音频解锁手势。

## WebRTC 语音（GM 控制）

- 语音默认关闭，仅团的归属 GM 可在准备中或进行中开启、关闭；开启状态在 GM 断线后保留，显式关闭、结团或服务端重启后结束。每次开启生成新的语音房间标识，断线自动重入必须仍指向同一次开启。
- 开启语音不等于自动采集：成员需点击加入，麦克风默认关闭，并在每次断线重连或浏览器权限状态变化后明确重新授权/启用。语音播放与现有 BGM/SE 通道独立，退出或暂停语音不得改变背景音乐和音效。
- GM 与玩家的语音面板提供本机麦克风选择和音频处理设置。可分别调整回声消除、浏览器降噪、自动增益、深度降噪、噪声门与压限器，深度降噪、噪声门与压限器默认开启。深度降噪可选 DeepFilterNet3（默认，高质量）或 RNNoise（轻量）；DeepFilterNet3 模型加载完成前及不可用时由 RNNoise 处理。深度降噪生效时替代浏览器降噪，噪声门只在检测到人声时放行，以压住说话间隙的呼吸声与底噪。面板显示浏览器报告的实际设置、当前降噪模型及处理回退状态。
- 麦克风测试提供输入电平和可选的本地回听，测试音频不会发送给其他成员。普通模式点击切换麦克风。按键说话模式支持可配置快捷键与面板内的按住按钮，松开或窗口失焦后停止发送，编辑文本时快捷键不触发。
- 采用浏览器 WebRTC 全网状点对点音频，不经过 CoGM 服务端转发媒体。实例人数上限默认 8（含 GM），可配置；GM 可在语音关闭时为单团设置更低的持久上限，最低 2。始终为 GM 保留一个位置，其余 PC/OB 按先到先入，满员不挤出现有成员；同一有效席位同一时间只能有一个语音标签页。
- 语音发言不受团内阶段限制（强制 CG 阶段仍禁止文字发言）。OB 默认仅收听，GM 可逐个授权或撤销，也可静音任意非 GM 成员。撤销授权、席位替换、释放与踢出会立即重算权限。
- 短暂断线可在同一语音开启中重连，不重放 SDP/ICE；同一有效席位在重连、主动离开再入时不能借此清除 OB 授权或 GM 静音。席位被替换、释放或踢出后清除这些运行状态。成员、房间、SDP/ICE 与运行静音均不写入团历史；运行时成员连接和 SDP/ICE 不写入数据库。
- 已加入成员可见当前成员列表；GM 未加入媒体时也可管理成员列表。其他未加入席位只看到可用状态与占用人数。TURN 临时凭据只向已加入成员下发。
- 发送端与接收端都必须依据权威状态停止采集、发送与播放；服务端同时限制信令只可在同一次开启的有效已加入成员之间单播。无法防止相互串通的浏览器客户端私自转发其已经收到的音频，因此不要把语音内容作为对恶意合谋参与者的保密边界。
- 语音诊断默认关闭。GM 和玩家可在语音面板阅读说明并同意记录，在加入语音时采集连接指标与状态事件。关闭开关会立即停止记录。点击「导出诊断日志」将当前标签页的日志下载为 JSON。日志不会通过 HTTP 或 WebSocket 发送，也没有 GM 后台导出入口。
- 每个标签页只保留当前团最近 240 条采样和 128 条事件。停止记录或离开语音后仍可导出已有日志。未关闭开关时，同团重新加入语音可继续采集。浏览器允许会话存储时，同一标签页刷新后仍可导出，采集须重新同意。切换到另一团会清除之前的日志，关闭标签页会结束本次存储。会话存储不可用时仅保留在当前页面内存。
- 诊断数据包含临时语音房间与成员标识，以及排障所需的 RTC 指标和事件。日志不含音频内容、聊天、IP、SDP、ICE 地址、账号标识、设备名称、设备 ID 或浏览器指纹。旧版上传的数据库记录原样保留，应用不再提供读取或写入入口。

## 情报管理（GM 发放）

- **情报（线索/Handout）**归属模组，GM 后台预先准备，条目包含：标题、文字内容、可选图片附件（地图、关键道具、手记等）。
- 团进行中由 GM 发放，两种可见范围：
  - **公开情报**：发给全体（含 OB）。
  - **秘密情报**：仅发给指定的一个或多个 PC，其余人（含 OB）不可见、也感知不到发放行为。
- 已发放的秘密情报可**追加**发放对象（如玩家之间共享线索后 GM 公开化）；v1 不提供独立的情报撤回操作，仅可通过回溯到锚点撤回其后的发放记录（见「历史与回溯」）。
- 玩家端收到情报时有醒目提示并弹出展示，之后可在"情报"面板随时回看自己已获得的全部情报。
- 情报可见性判定为服务端权威：秘密情报只推送给可见者，禁止广播全员后由前端隐藏。
- 中途加入、断线重连的玩家能收到对其可见的全部已发放情报。
- 玩家点「收下」后，服务端按「玩家 × 发放记录」持久化已读；重连、刷新、重新入团都不会再次弹出已读情报（情报面板中可回看，未读条目带「未读」标记）。
- GM 端按情报显示发放状态、接收者与已读回执：秘密情报列出每位接收者的已读/未读，公开情报显示已读人数；已发放的秘密情报可直接向新增 PC 追加。

## 历史与回溯（溯洄）

### 历史回看

- **GM 导演工作台**：对话面板顶部新增「历史」入口，打开宽幅覆盖层——左侧为时间线，右侧为所选锚点的状态摘要与「回到这里」；支持搜索、发言者多选与事件类型筛选。「已归档」分段查看历次回溯/撤销移出的内容，「审计」分段查看被驳回与已丢弃的发言。
- **玩家沉浸视图**：聊天面板头部提供「历史」按钮，另有 `H` 快捷键打开视觉小说式全屏历史覆盖层（输入框聚焦时不触发，`Esc` 关闭）；覆盖层支持搜索、发言者多选与「回到最新」。结团后由「查看记录」按钮打开同一历史。
- 时间线按呈现顺序包含：对白/主持人发言、掷骰与已完成鉴定卡、场景切换、阶段变化、情报发放、表情变化。HP/MP/SAN 与成长标记等状态变更只进入 GM 历史；已驳回与已丢弃发言只进入 GM「审计」分段，不可作为锚点。
- 玩家历史由服务端按可见性过滤：包含对其可见的记录（含加入前的公开记录），不包含自己的待审/未通过发言，也不包含因回溯或撤销回溯而归档的内容。
- 已结团后历史只读，不可回溯或撤销。

### 溯洄（GM 回溯）

- 仅 GM 可用。当前活动时间线中的任意条目（回溯记录本身除外）都可作为锚点；「回到这里」撤销该条目及其之后的全部时间线内容，执行前展示预览并要求二次确认。
- 恢复团阶段、角色团内状态、当前场景指针与人物表情；锚点之后的情报发放、接收者与已读记录撤回；锚点后完成的鉴定结果作废，锚点前已发出但未完成的鉴定请求恢复为待响应，锚点前不存在的请求删除；整个待呈现队列清空并通知作者。
- 不恢复 BGM/SE、舞台布局与缩放、席位认领、踢人/黑名单/在线状态、团可见性设置与团内 NPC 编组。
- 团结束前可「撤销本次回溯」，按后进先出（LIFO）恢复上一次回溯前的时间线与状态，并把回溯后新产生的已呈现内容移入「已归档」。
- 玩家在线时收到显式回溯事件与系统提示；离线玩家重连后由快照提示。

## 在线管理与黑名单

- GM 可查看当前在线玩家（含所选 PC/OB 身份）。
- GM 可踢出玩家：踢出即在本团内禁入，立即断开连接，且在 GM 解除禁入前无法重新认领席位或进入本团。
- GM 可在「在线管理 → 已踢出」查看禁入名单并逐个解除禁入，解除后玩家可正常重新进入；禁入只作用于当前团，不影响该玩家参与其他团。
- GM 可将玩家的浏览器指纹拉入黑名单，支持设定时长（含永久）。
- 指纹为尽力而为的标识，不假设其绝对可靠。

## 全局软删除与回收站

- 运行时业务代码不对任何表执行物理 `DELETE`，覆盖账号、人物、模组、团、场景、媒体、模板、提交、邀请、关联表、登录会话与临时导入记录；图片、音频、主题包等实际文件同样保留，本期不做物理粉碎或自动清理。
- 解除关联、撤销邀请、退出登录、清理过期数据都只写状态或删除时间。
- 软删除不级联破坏历史：已删除资源停止新使用，旧团仍可读取；进行中的团可继续显示当前内容，直到 GM 切换。
- 每个所有者有按所有权隔离的回收站与恢复入口；admin 的回收站只含账号，不因此获得 GM/PL 内容权限。
- 已删除资源的名称/用户名继续占用，恢复后重新可用。成长、审计、聊天、骰点、人物版本为追加式历史，不提供用户删除/编辑。

## UI

- 简洁优雅。全站统一深色主题（以墨色为底），玩家沉浸视图、PL 工作台、GM 后台与 admin 控制台共用同一套语义设计 token。
- **主题自定义（自部署）**：主题包由 admin 安装与管理，可替换进团页、玩家沉浸视图、GM 控制台与 GM 后台的页面级布局、视觉与站点文案。主题按模组选择、作用于该模组的玩家；GM 界面主题为实例级设置（admin 管理）。内置默认主题不可删除，任意页面可用 `?theme=default` 强制回退。入口页与登录页固定使用默认主题。主题包格式、制作与安装见 `docs/theme-system.md`。
- 统一登录页 `/login` 按账号角色跳转：admin → `/admin`，gm → `/gm`，pl → `/pl`。匿名 OB 从 `/join/$sessionId` 进入。
- 首页入口支持直接输入完整 UUID 或 `/join/<uuid>` 邀请链接，也支持输入 6 位十六进制短编号（含 `#` 前缀或 `/join/<短编号>`）；短编号通过公开解析接口校验唯一性后再跳转，不存在或存在前缀碰撞时在首页提示且不泄露候选团 ID。
