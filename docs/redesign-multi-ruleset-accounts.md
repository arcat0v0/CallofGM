# 重设计：多规则、账号、人物与模板

状态：已确认，按阶段实施。本文是实现基准；与旧实现冲突处以本文为准。没有旧部署，允许破坏性重构数据库与协议，不保留旧数据兼容层。

## 1. 目标与边界

本期完成四组能力：

1. **账号与所有权**：`admin` / `gm` / `pl` 三类账号完全分离；所有业务资源有明确所有者；匿名 OB 保留。
2. **多规则基础**：规则系统带版本与元数据；模组、团、人物、模板创建时显式选择规则，创建后不可切换。
3. **人物生命周期**：PL 独立建卡；人物版本、成长记录、GM 终生字段修改审计；提交链接、审核、入团、团内快照与显式同步；结团成长回写。
4. **模板与快速开团**：模板是可编辑的模组快照，支持显式保存历史版本；可从模板创建模组或一次性快速开团。

全局软删除贯穿所有业务资源：运行时不对任何表执行物理 `DELETE`，实际文件同样保留。

非目标：跨 GM 共享、共同主持、规则上传/启停后台、公开注册、全站 PL 角色库搜索目录、角色占用锁、文件物理粉碎或自动清理。

## 2. 账号与认证

### 2.1 角色

| 角色 | 能力 | 明确不能做 |
|---|---|---|
| `admin` | 管理账号、实例设置、主题包 | 查看 GM 模组/团/人物内容；控场；查看 PL 私密角色库 |
| `gm` | 管理自己的模组、NPC、预建 PC、团、模板、回收站 | 管理账号与主题包；访问其他 GM 的资源 |
| `pl` | 管理自己的人物库、参与团、提交审核、修改密码 | 建团/建模组；查看其他 PL 的人物库 |

角色在账号创建时固定，不提供角色继承或互相转换。需要另一身份必须另建账号。所有账号共用同一登录入口与同一会话机制。

### 2.2 用户与登录

- 用户名全局唯一、不区分大小写（`username_normalized` 唯一索引），保存展示用原始拼写。
- 密码使用 `Bun.password` 哈希；强度下限由服务端 zod 校验。
- 无公开注册。`admin` 创建账号；首个 `admin` 通过运维命令 `bun run setup:admin` 创建。
- 用户可改自己的密码；`admin` 可重置任意账号密码。
- 所有账号同一时刻只有一个活动浏览器会话：
  - 登录成功即为该账号创建新会话，并在同一事务内撤销该账号全部旧会话。
  - 同浏览器多标签页共享 HttpOnly Cookie，因此同时可用。
  - 新浏览器登录顶替旧会话后，服务端立即断开该账号全部 WS 连接；旧浏览器下一次 HTTP/WS 请求得到 401。
- 密码修改撤销该账号全部其他会话并保留当前会话；admin 重置密码与禁用账号撤销全部会话。
- 禁用（`disabledAt`）与软删除（`deletedAt`）都阻止登录。软删除后用户名永久占用，可恢复。
- 至少保留一个未禁用、未删除的 `admin`；停用/删除/改角色前服务端校验。

### 2.3 匿名 OB

- 匿名玩家仍通过指纹签发 30 天 `player_token`，只能进入 OB 席位。
- PC 席位必须由 `pl` 账号持有。
- 已登录的 `pl` 也可以选择 OB，此时席位持有者类型为账号。
- `admin` / `gm` 不能认领玩家席位；GM 只能以 GM 身份进入控制台。

### 2.4 会话持有者

`session_claims` 不再只指向匿名玩家，而是持有者二选一：

- `holder_kind = 'user'`：`user_id`（`pl` 角色）
- `holder_kind = 'anonymous'`：`anonymous_player_id`

同一团内同一账号、同一匿名玩家、同一角色仍各自最多一条未释放席位。团内禁入按持有者记录；指纹黑名单继续用于匿名与联邦识别，账号被禁用同样会断开其连接。

## 3. 所有权与可见性

每张业务主表增加 `owner_id`：

| 资源 | 所有者 | 说明 |
|---|---|---|
| 模组 | GM 账号 | 团继承模组规则；模组路径、场景、曲目、情报随之归属 |
| 团 | GM 账号 | 显式记录，不依赖模组推导，便于列表过滤与迁移 |
| 人物 | GM 或 PL | NPC 必须 GM；PL 人物必须 PC；GM 预建 PC 分配后转归 PL |
| 模板 | GM 账号 | 模板 NPC 是 GM 角色库里的普通人物 |
| 媒体资产 | 上传者账号 | 逻辑引用可跨资源，但读取仍按引用链鉴权 |
| 提交/邀请/审核 | 发起 GM 或提交 PL | 按目标模组/团所属 GM 过滤 |

通用规则：

- GM 的每个列表查询都带 `owner_id = actor.userId`；不存在、属于他人、已删除的资源一律表现为 404，避免泄漏存在性。
- `admin` 不进入任何 GM / PL 内容路由；其账号管理接口不返回角色库、模组或团内容。
- 公开范围仅限：入团信息、玩家自身可见的快照/事件、我的人物、我的提交、我参与的团。
- 媒体读取在现有“GM / 当前场景 / 团内曲目 / 参团人物立绘 / 情报接收名单”判定上增加所有者维度：GM 只能读自己的媒体，PL 只能读自己人物的立绘与已获得情报的附件。

## 4. 多规则抽象 v2

### 4.1 规则标识与注册

- `RuleId` 在协议层是受限字符串（小写字母、数字、连字符，最长 50），不再固定为 `coc7e` 枚举。合法性由服务端注册表在运行时校验。
- 服务端 `RuleRegistry` 是唯一注册点；启动时注册所有内置规则。每个规则提供不可变元数据：

```ts
interface RuleMetadata {
  id: string;
  name: string;
  version: string;      // 规则实现自身 semver
  apiVersion: 1;        // 与核心契约兼容版本
  description: string;
  permanentSheetFields: string[];
}
```

- `GET /api/v1/rules` 返回所有已注册且 `apiVersion` 与核心兼容的规则元数据。前端选择器只消费该接口，不硬编码规则列表。
- 本期只注册真实可玩的 CoC 7e，不做占位规则。以后新增规则只需新增实现并在注册表注册，选择器自动出现。

### 4.2 创建与不可变性

- 创建模组、模板、人物必须显式提交 `ruleId`；服务端与前端都没有默认规则。
- 团从模组继承规则并在创建时写入自己的 `rule_id`；人物提交入团时校验与团规则一致。
- `ruleId` 创建后不可修改；更新请求不包含该字段，仓储层不提供修改入口。
- 同一 PL 可拥有不同规则的多个人物；单个人物不跨规则。

### 4.3 规则实现职责

`RuleSystem` 在现有能力之上增加：

- `metadata` 元数据。
- `createEmptySheet()`：新建人物时的规则空卡。
- `describeSheet()`：可选的字段描述，用于通用展示；建卡交互仍由前端规则专属组件提供。
- `sheetVersion` / schema 迁移钩子预留（本期 CoC 为 1）。
- 允许的扩展项声明：CoC 允许新增自定义技能（名称、基础值、当前值），不允许自定义属性、公式、成功等级或特殊检定。
- `permanentSheetFields`：本规则声明 GM 可跨团修正的“终生字段”。CoC 7e 为九项属性（STR/CON/SIZ/DEX/APP/INT/POW/EDU/LUCK）。

前端规则注册表按 `ruleId` 提供建卡组件、人物卡编辑组件、人物卡展示组件、检定面板与团内状态视图。业务页面通过注册表取组件，不直接 import `coc7e`。服务端通用模块只通过 `RuleRegistry` 取实现。

## 5. 人物

### 5.1 数据模型

人物由五部分组成：

1. **通用资料**：姓名、简介/背景、PC 或 NPC、所有者、规则。
2. **独立表情列表**：每项有键、显示名、立绘资产、排序、是否默认；可增删、命名、排序、设默认。内置预设只在建卡时作为初始模板。
3. **规则人物卡**：`sheetJson`，由规则 schema 校验；CoC 包含九属性与技能表（含自定义技能）。
4. **版本**：`sheetVersion`（规则卡版本）与 `profileVersion`（姓名/背景/立绘版本）；整体 `version` 用于乐观并发。
5. **历史**：人物版本、成长记录、GM 修改审计，全部追加式，不提供用户编辑或删除。

人物表保留当前内容作为读取快路径；`character_versions` 保存每次完整快照（姓名、背景、规则卡、所有者、类型），用于审核绑定、差异预览与历史回看。

### 5.2 所有权转换

- PL 创建的人物固定为 PC，所有者是 PL。
- GM 可以预建 PC（所有者暂为 GM），通过分配操作把 `owner_id` 转给 PL；转移后由 PL 管理。
- NPC 始终归 GM。
- PL 人物不能转为 NPC；需要 NPC 时由 GM 创建独立副本，记录来源人物 id。

### 5.3 版本与审核

- 审核记录绑定 `sheetVersion`：改动规则数值、技能或终生字段后，之前通过的审核视为过期，需要重新审核。
- 仅改姓名、背景、简介、立绘只提升 `profileVersion`，不要求重新审核；GM 始终能看到最新资料。
- 每条审核记录：目标范围（模组/团）、目标 id、人物 id、提交版本、状态、决定 GM、决定时间、理由。
- 模组链接审核通过后建立模组-人物关联；团链接审核通过后创建团内 PC 席位记录，并以审核通过的 `sheetVersion` 初始化团内快照与状态。
- 审核通过不自动认领，不为 PL 建账号，不分配席位。

### 5.4 提交链接

- GM 为某个模组或团创建提交链接；链接默认 7 天有效，可撤销。
- 链接要求 PL 登录，只用于：
  - 提交一个新建人物；
  - 从自己的人物库选择一个已有、同规则且可提交的人物。
- 提交时冻结所提交的 `sheetVersion` 与资料快照。链接不批准、不分配席位、不建账号。
- 撤销链接只阻止新提交，已提交的审核记录继续处理。
- 审核待办按目标所属 GM 查询；PL 可查看自己的提交状态与理由。

### 5.5 团内快照与同步

- `session_characters` 保存加入时的完整人物快照：姓名、背景、规则卡、`base_sheet_version`、`base_profile_version`。团内检定、状态初始化与人物卡展示读取该快照，不读主卡。
- 主卡后续修改不自动同步到任何进行中团。
- 同一人物可同时用于多个未结团，各自维护独立快照与 `session_character_state`。
- GM 可查看主卡与团内快照的逐字段差异；显式同步时选择字段并提交，服务端校验双方版本后更新快照。同步不覆盖团内伤害、状态、成长标记与团内当前表情。
- 并行修改：更新请求携带 `expectedVersion`。增量成长可累计；若同一字段被并发修改且版本不匹配，返回 409 与最新版本，要求重新确认，禁止整卡静默覆盖。
- 表情与立绘按人物 id 实时引用，不进入团内快照；新增表情对已入团者立即可见。

### 5.6 GM 终生字段修改

- GM 只能修改规则声明的 `permanentSheetFields`。CoC 为九属性。
- 每次修改记录：人物、团（若在团内）、GM、字段、旧值、新值、时间、可选原因。写入追加式审计并向 PL 展示。
- 修改提升 `sheetVersion`；若该人物有已通过审核，标记为需重新审核。
- 姓名、背景、立绘只由 PL 修改；GM 不提供这些字段的编辑入口。

### 5.7 成长

- 团内鉴定成功继续写 `growthMarks`（暗骰写 `hiddenGrowthMarks`）。
- 结团时 GM 审核成长：为每个成长技能填写增量（可为零），确认后：
  - 主卡技能按增量累加；
  - 追加成长记录（人物、团、技能、旧值、新值、GM、时间）；
  - 提升 `sheetVersion`；
  - 历史团保留当时快照，不被回写。
- 成长确认使用乐观并发；若主卡技能在此期间被其他团或 PL 改动，采用增量累加；若发生冲突性覆盖，要求基于最新版本重新确认。
- 能够查看某人物 GM 可见其完整成长与修改历史（含其他团记录），不按团裁剪。PL 只能看自己的人物。
- 不提供全站 PL 角色库搜索目录。

### 5.8 自动认领

- PL 通过明确的团链接进入，且该团只有一个可认领的已审核 PC 时，登录后自动认领。
- 存在多个可认领 PC 时显示选择页。
- 普通登录只进入 PL 工作台。
- 自动认领不自动批准人物，也不会同时打开多个团。

## 6. 模组、团、模板

### 6.1 模组与团

- 模组创建必须选择规则，创建后不可切换；模组归属创建 GM。
- 团创建必须选择自己的模组；团记录 `owner_id` 与 `rule_id`，规则不可切换。
- 团实时引用模组的场景、曲目、情报：GM 新增资源后现有团立即可用。这是刻意保留的能力。
- 删除模组不级联破坏已存在团：已删除模组停止新建团与新引用，旧团仍可读取当时内容。

### 6.2 模板

模板是独立的、可编辑的模组快照，与源模组和已实例化模组都不自动同步。

模板包含：

- 场景、曲目、情报、团设置；
- NPC 副本（作为正常人物进入 GM 角色库，记录模板来源）；
- 主题引用（只存 `themeId`，主题缺失时回退默认主题）。

模板不包含：PL 主人物、账号、席位、成长、运行记录。

模板版本模型：

- 模板始终有一份“当前内容”，直接编辑只改当前内容。
- 可显式“另存为版本”；版本是不可变快照。
- 实例化默认使用当前内容，也可选择任一已保存版本。
- 新建模组记录来源模板与版本；快速开团同理。

实例化语义：

- 新建独立的模组、场景、曲目、情报与 NPC 人物行；媒体文件可复用同一存储资产，但逻辑引用互不影响。
- NPC 副本拥有新的角色 id，记录 `origin_template_id` / `origin_template_version`。
- 模板版本快照保存资源字段与媒体资产 id；不复制二进制文件。

### 6.3 快速开团

- 一次操作创建独立模组 + 一个处于“等待开始”的团。
- 允许暂时没有任何 PC；之后通过提交链接邀请与审核。
- 模组与团归属操作者，规则来自模板且不可切换。
- 失败时整体回滚，不留下半个模组或半个团。

## 7. 全局软删除

### 7.1 约束

- 运行时业务代码不对任何表执行物理 `DELETE`，覆盖账号、人物、模组、团、场景、媒体、模板、提交、邀请、关联表、登录会话、临时导入记录。
- 解除关联、撤销邀请、退出登录、清理过期数据都只写状态或删除时间。
- 图片、音频、主题包等实际文件保留；本期不做物理粉碎或自动清理。
- 数据库外键不使用会在运行时触发的物理级联；删除父资源不得靠级联清空子表。
- 删除是幂等操作；重复删除不报错。
- 唯一约束需与软删除共存：软删除后再次创建同一逻辑关联时恢复原行，而不是插入重复行。

### 7.2 读取语义

- 已删除资源停止用于新引用与新流程：不能再建团、入团、认领、发放、作为新表情等。
- 已存在并引用该资源的团仍可读取：当前场景、正在播放的曲目、已发放情报、团内人物快照继续可读，直到 GM 显式切换或替换。
- 删除人物不影响已入团快照；删除模组不影响已建团。
- 所有列表默认过滤已删除；管理员/所有者回收站显式包含已删除。

### 7.3 回收站

- 每个所有者有独立回收站，只显示自己的已删除资源；admin 的回收站只含账号。
- 支持恢复；恢复后重新进入正常列表。
- 恢复受约束校验：父资源已删除时，子资源恢复需父资源先恢复，或返回明确冲突。
- 已删除用户名不可被新账号占用，只能恢复原账号。

## 8. 协议与接口变更

### 8.1 认证

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/auth/login` | 用户名 + 密码；成功撤销旧会话并写 HttpOnly Cookie |
| POST | `/api/v1/auth/logout` | 撤销当前会话 |
| GET | `/api/v1/auth/me` | 返回 userId、username、role |
| PUT | `/api/v1/auth/password` | 自助改密 |

匿名 OB 保留 `POST /api/v1/player/identity`。

### 8.2 管理端

| 方法 | 路径 | 说明 |
|---|---|---|
| GET / POST | `/api/v1/admin/users` | 列表 / 创建账号 |
| GET / PATCH | `/api/v1/admin/users/:id` | 详情 / 禁用、启用、软删除、恢复（角色不可改） |
| POST | `/api/v1/admin/users/:id/password` | 重置密码并撤销全部会话 |
| GET / POST | `/api/v1/admin/themes` | 主题包管理（从 GM 后台迁移） |
| GET / PUT | `/api/v1/admin/ui-settings` | 实例级 GM 界面主题 |

### 8.3 GM 端

- 模组、场景、曲目、情报、人物、团、媒体：现有路径保留，增加所有者过滤；所有创建请求必须带 `ruleId`（人物/模组）或从模组继承（团）。
- 新增：
  - `/api/v1/gm/templates` 与 `/api/v1/gm/templates/:id/versions`、`/instantiate`、`/quick-start`
  - `/api/v1/gm/invites`（模组/团提交链接）
  - `/api/v1/gm/reviews`（待办、通过、拒绝）
  - `/api/v1/gm/characters/:id/growth`（历史）

## 10. 前端结构

- 统一 `/login`，按 `role` 跳转：`admin` → `/admin`，`gm` → `/gm`，`pl` → `/pl`。
- `/admin`：账号管理、主题包、实例设置。
- `/pl`：我的人物、参与团、提交记录、回收站、账号设置。
- `/gm`：模组、NPC/预建 PC、团、模板、审核待办、回收站。
- `/submit/$token`：PL 提交页。
- 规则专属组件放 `apps/client/src/rules/{ruleId}/`，经客户端规则注册表按 `ruleId` 取用。
- 创建模组/模板/人物时规则选择器数据来自 `GET /rules`；没有默认选项，必须手动选择。
- 现有直接 import `coc7e` 的页面改用规则注册表或共享的规则无关视图模型。

## 11. 分阶段实施与验证

### 阶段一：账号、所有权、多规则基础、软删除

步骤 → 验证：

1. 迁移与 schema：users/user_sessions/owner_id/deleted_at → `bun run db:check`、迁移在空库可重复执行。
2. 认证与管理端：登录顶替、禁用/删除撤销会话、至少一个 admin → 集成测试覆盖三角色登录、旧会话失效、admin 越权读内容 403/404。
3. 所有权过滤：GM/PL 资源列表与详情 → 跨 owner 集成测试，他人资源表现为 404。
4. 规则注册与选择器：`GET /rules`、创建必须带 ruleId、不可切换 → 集成测试缺 ruleId 400、切换 400、元数据列表。
5. 软删除：业务仓储无物理 DELETE、回收站恢复 → 静态扫描 + 集成测试验证删除后旧团可读、新引用被拒、恢复可用。

### 阶段二：人物、版本、成长、PL 流程

1. 人物通用资料、表情排序、版本表 → 单元/集成测试。
2. PL 人物库 CRUD 与版本冲突 → 409 冲突、增量成长累计。
3. 提交链接、审核、入团 → 审核版本绑定、过期重审、团内快照初始化。
4. 团内快照与显式同步 → 差异预览、字段选择、状态不被覆盖。
5. GM 终生字段审计、结团成长确认 → 审计记录、成长回写、历史团不变。
6. 自动认领 → 单 PC 自动认领、多 PC 选择页。

### 阶段三：模板与快速开团

1. 模板当前内容与版本保存 → 直接编辑不影响已保存版本。
2. 从模板创建模组 → 资源独立、媒体可复用、NPC 副本记录来源。
3. 快速开团 → 一次创建模组 + 等待团、失败整体回滚、可暂无 PC。
4. 模板回收站与恢复 → 所有者隔离。

每个阶段完成时运行：`bun test`（相关包）、`bun run typecheck`、`bun run check:boundaries`；前端改动按项目要求使用 Biome。浏览器视觉验证由用户执行。

## 12. 已决补充（2026-11-03）

- **回溯是软删除的唯一例外**：团内运行态数据（`check_requests`、`handout_grants`、`handout_grant_recipients`、`handout_reads`）在 GM 回溯与撤销回溯时仍按现有实现物理删除并重建，因为它们是可从时间线重算的运行态，不是业务资产。软删除约束覆盖账号、人物、模组、团、场景、媒体、模板、提交、邀请、关联表、登录会话与临时导入记录。
- **实例设置归 admin**：`ui_settings.gmThemeId`、主题包安装/删除/重扫全部迁移到 `/api/v1/admin/*`；GM 控制台不再提供主题浮钮与主题选择入口，GM 后台的主题管理页移除。
