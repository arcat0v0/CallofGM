# 舞台浮层玻璃材质统一设计

日期：2026-11-05

## 意图与原因

玩家舞台中的场景卡片、音乐控件、工具坞、对话框和聊天浮岛分别使用不同的 MD3 表面色与透明度，削弱了同一场景内的视觉一致性。本次以用户偏好的场景卡片为基准，将浮层材质收敛到全局 token 与共享工具类。

## 目标

- 舞台浮层统一使用 `surface-container-low` 的 72% 半透明背景、一致的边框和 24px 背景模糊。
- 场景卡片、音乐控件、工具坞、舞台对话、聊天浮岛、展开聊天按钮、玩家工具浮层和 GM 浮岛复用同一个 `stage-glass` 工具类。
- 后续只需调整 `theme.css` 中的 token 或共享工具类即可整体调整材质。

## 非目标

- 不改变布局、圆角、阴影层级、交互、消息气泡、输入控件或后台普通卡片。
- 不把全屏遮罩、模态框背板或立绘内容本体改成透明材质。
- 不引入新依赖或另一套颜色体系。

## Approaches

### 方案 1：全局 stage-glass 工具类（已选择）

在 `theme.css` 定义舞台浮层颜色与模糊 token，在 `expressive.css` 定义共享 `stage-glass` 工具类，各浮层只保留自己的布局和阴影。修改集中、运行时主题仍可继承 MD3 角色色，符合项目 token 单一来源约束。

### 方案 2：逐组件替换透明度类

直接把现有 `/80`、`/85`、`/90`、`/92` 改成 `/72`。改动看似更少，但背景、边框和模糊仍散落，后续容易再次漂移，因此不采用。

### 方案 3：共享 React 浮层组件

新建统一浮层组件包裹所有场景。会同时改变组件结构与插槽边界，对纯视觉任务范围过大，因此不采用。

## 验证

- 组件测试断言关键浮层使用 `stage-glass`，防止局部样式回退。
- 对改动文件运行 Biome、客户端测试、类型检查和生产构建，确认 Tailwind 工具类真实生成。
- 在本地开发团通过临时观战席对同一舞台进行修改前后截图对比，检查文字对比度、背景透出和整体一致性；结束后退出临时席位。
