# CoC 7e 玩家整卡式车卡页设计

状态：已确认（2026-11-06）

## 目的

用一个完整、可反复修改的长页替代 PL 新建人物弹窗。玩家应能在同一页理解并填写一张 CoC 7e 人物卡，看到规则公式、职业技能点和兴趣技能点的实时核算，同时保留自定义职业、专攻、技能、背景与装备的创作自由。

当前 PL 独立建卡和邀请链接新建只提交姓名、背景及全 50 的空卡。本设计复用已经实现的 sheet v2、技能目录、28 个职业与派生公式，不建立第二套人物数据模型。

## 目标

- 所有建卡字段集中在一张可滚动的整卡页面，不按强制步骤拆分。
- 属性、技能、职业、年龄和时代的规则提示紧挨对应字段。
- HP、MP、SAN、MOV、DB、体格、半值和五分之一值实时更新。
- 职业技能点、兴趣技能点、信用评级和资产建议实时核算。
- 标准技能、专攻、自定义职业与自定义技能均可编辑。
- 完整编辑背景、武器、护甲、装备、资产、法术、神话典籍与遭遇记录。
- 独立建卡和邀请链接新建共用同一编辑器与校验逻辑。
- 刷新或暂时离开页面不会丢失未提交内容。

## 非目标与边界

- 不实现自动掷骰建卡或自动随机属性。
- 不强制玩家耗尽职业技能点或兴趣技能点；点数、信用范围和年龄调整属于醒目提示，schema 合法性错误才阻止提交。
- 年龄只自动影响 MOV；属性扣减和 EDU 增强次数显示为建卡提示，不擅自改值。
- 不新增结构化背景经历系统，继续使用现有背景文本。
- 不在人物创建前上传立绘；创建成功后沿用现有资料编辑器添加立绘。
- 不修改 Excel 解析器、GM 建卡流程、团内状态或审核规则。

## 已考虑的方案

### 整卡式长页（用户已选择）

页头提供返回、草稿状态和唯一主操作；下方依次呈现身份与职业、属性与派生值、完整技能、背景、战斗装备、资产、法术与神话记录、最终检查。优点是整卡关系清楚、便于反复比较和修改，也最接近纸卡心智模型。挑战是内容密度高，需要通过分组、对齐和渐进展开控制长度。

### 章节式工作台

左侧章节导航，中间单章节编辑，右侧实时人物卡。规则引导和预览较强，但用户没有选择；跨章节对照需要频繁切换。

### 逐步向导

每一步只显示少量字段，以上一步和下一步推进。新手引导最直接，但修改效率低，也不符合本次选择的整卡体验。

## 页面与入口

新增 `/pl/characters/new`，仅 PL 可访问。人物库的顶部和空状态“新建人物”按钮改为导航到该路由，删除该文件内仅用于空卡创建的局部 `CharacterEditor`；现有人物编辑继续使用独立的 `CharacterProfileEditorDialog`，不受影响。

独立建卡要求玩家显式选择服务端返回的规则；本期只有 CoC 7e，但不提供默认选中项。邀请新建时规则由邀请信息锁定，不显示可修改的规则选择器。

`/submit/$token` 保留“新建/已有人物”选择和已有人物提交。选择新建后进入 `/pl/characters/new?invite=<token>`；未登录 invitee 沿用现有守卫先到 `/login`，登录成功后通过 `returnTo` 返回原邀请链接，再进入新建页。草稿和提交始终绑定已登录的 PL `userId`，不支持匿名建卡。邀请 token 只用于加载邀请信息和最终提交，不先创建人物再关联。完成页沿用现有提交成功反馈。

通用页面壳负责规则加载、邀请上下文、草稿、提交和离开确认；规则专属表单由客户端规则注册表提供。通用业务组件不直接 import CoC 7e，具体表单放在 `apps/client/src/rules/coc7e/`。

沿用 PL 工作台现有品牌、字体、语义 token 和基础组件。视觉采用已抽取的 `true-black-flat` 方向，但保留项目墨色地面与萌黄 accent，不改写全局主题；以明暗层级和间距组织表面，不加发光、渐变或装饰性仪表盘。抽取的 builder 图形节点布局无法承载长表人物卡，因此页面结构采用 app screen 的表单规范，不采用节点画布。

桌面使用居中的宽幅单栏，标题保持应用页尺度；字段按内容分为二至四列，派生数值使用同一行的分组统计带，而不是独立 KPI 卡片。手机保持同一阅读顺序，所有字段和保存操作可用，不出现横向页面滚动。章节锚点可作为紧凑的横向跳转条，但不把页面改回多标签编辑器。

## 表单内容与规则行为

### 身份、时代与职业

编辑姓名、时代、年龄和职业。时代为 1920s 或现代；职业可选择 28 个参考职业或自定义职业。现代专属职业只出现在现代时代；切换时代不删除已经填写的技能或自定义内容，只显示需要玩家确认的提示。

选择职业预设填入职业名称、信用范围、公式选项与推荐本职技能，但不重置属性或技能。存在多个职业技能点公式时由玩家明确选择。自定义职业允许编辑名称、信用范围和本职技能；公式不引入表达式解析器，而是通过现有结构化“属性 + 1–8 倍倍率”条目组合，沿用 `Coc7eOccupation.skillPointFormula` 的范围和最多四项限制。

切换到 1920s 时若当前是现代专属职业，为保留创作内容，将该职业转为自定义：保留名称、公式、信用范围和本职技能，仅清除 `presetId` 并显示提示；不删除技能，也不把这种情况作为 schema 错误。

年龄旁显示对应年龄段的官方建卡提示；MOV 由共享公式实时计算。

### 属性与派生数值

九项属性均使用整数输入，合法范围 1–99。每项同时显示半值和五分之一值。输入期间允许暂时为空， blur 或提交时给出字段级错误，不把空值静默改成 0。

派生区显示 HP 上限、MP 上限、初始 SAN、SAN 上限、MOV、DB、体格与重伤阈值，全部由 `deriveCoc7eSheetStats` 计算，客户端不复制公式。这里展示的是主卡建卡值，不创建或修改任何团内状态。

### 技能、专攻与点数账本

完整技能目录按类别分组，支持搜索和按“已提升/本职/专攻”筛选。每行显示基础值、当前值、半值和五分之一值；未修改项以基础值参与预览。沿用已确认的稀疏存储边界：只持久化玩家显式填写的技能值与自定义定义，未修改的目录项不写入映射，筛选或收起分组不能清除已有值。

技艺、科学、格斗、射击、驾驶、生存和学识通过明确的专攻名称添加；同一父技能可添加多个专攻。自定义技能同时填写名称和基础值。所有值遵循 shared schema 的 0–999 范围。

本职技能集合存入 `occupation.skillKeys`。选择预设的泛型技能时，玩家把它落实为具体专攻；也可把符合创作设想的其他技能设为本职。信用评级始终计入职业技能点。

新增 shared 纯函数计算建卡账本：

- 职业技能点预算来自职业公式；兴趣技能点预算为 INT×2。
- 单项支出为 `max(0, 当前值 - 基础值)`。
- 本职技能与信用评级计入职业支出，其余技能的正向增量计入兴趣支出。
- 降低技能不产生负数退款。
- 显示预算、已用和剩余；超支、未用完或信用越界产生提示，不强制阻止创建。

### 背景、战斗与资产

背景沿用现有 4000 字文本，并提供可折叠的创作提示，例如重要之人、意义非凡之地、宝贵之物、特质与恐惧；提示只帮助写作，不拆成新字段，也不要求逐项作答。武器、护甲、装备、资产明细、法术、神话典籍和遭遇记录覆盖 sheet v2 的每个字段，支持增加、编辑和移除条目；空分组保留标题和清晰的添加入口。

资产区按时代与信用评级显示生活水平、现金、其他资产和消费水平建议。只有玩家点击“采用建议”才写入对应字段，切换信用或时代不自动覆盖已输入资产。

### 最终检查与提交

页尾汇总 schema 错误和规则提示。姓名缺失、未显式选择规则、字段越界或 sheet 解析失败阻止提交并定位到对应字段；点数未分配完、年龄调整未执行等仅作为提示。

独立模式调用 `POST /pl/characters`，提交姓名、背景、规则和完整 `sheetData`，成功后清除草稿并进入人物库。邀请模式调用现有 `/pl/invites/:token/submissions` 的 `mode: "new"` 分支，直接提交完整卡，成功后清除草稿并显示提交完成状态。

请求失败保留全部输入并显示服务端错误，不自动重试写请求。提交期间禁用重复提交。

## 草稿与离开行为

草稿保存在当前浏览器的 localStorage，键包含账号和独立/邀请上下文；内容包含版本、姓名、背景、规则与完整 sheet，不扩大服务端数据或权限范围。

编辑后防抖保存，页面打开时自动恢复有效草稿并显示“已恢复草稿”和“清空重填”。损坏或版本不兼容的草稿不进入表单，保留页面可用并提示重置。localStorage 不可用或写入失败时继续允许建卡，明确显示“草稿未能保存”，不影响最终服务端提交。独立创建或邀请提交成功后删除对应草稿。

有未提交改动时，返回人物库或切换入口需要确认；仅离开页面不删除草稿。清空重填需要二次确认。

## 实现边界

- 现有 `POST /pl/characters` 与邀请 `mode: "new"` 已接收 `background` 和完整 `sheetData`，并通过对应 `RuleSystem.characterSheetSchema` 做服务端校验和持久化；本设计不新增服务端数据模型，只用真实路由集成测试验证完整卡与 400 失败路径。
- 在客户端 `RuleComponent` 注册表增加规则专属建卡编辑器能力，由 CoC 7e 实现完整表单。
- 在 `packages/shared/src/rules/coc7e/` 增加建卡账本与年龄提示等纯函数，并通过现有命名空间导出。
- 复用 `Input`、`Textarea`、`Select`、`Button`、`Badge`、现有表单字段与反馈组件，不新建平行 UI 套件。
- 不新增代码注释；样式只使用现有 Tailwind utility 和语义 token。
- 保留用户已有的 `index.tsx`、`login.tsx` 修改，不做无关重构。

## 验证

1. Shared 单元测试：职业/兴趣点数、基础值差分、信用评级归属、降低技能不退款、自定义技能和专攻、年龄提示与公式边界。
2. 客户端组件测试：完整字段往返、输入暂空与非法值、职业切换不重置技能、时代与自定义内容保留、派生值同步、筛选不丢字段、资产建议需显式采用。
3. 提交流程测试：独立 POST 的完整 payload、邀请 new submission 的完整 payload、失败保留输入、重复提交防护、成功清草稿。
4. 草稿测试：刷新恢复、上下文隔离、损坏数据、清空确认和离开确认。
5. 服务端现有集成入口验证完整 sheet 创建及 400 校验，不以客户端 mock 代替真实持久化验证。
6. 隔离数据库与端口的浏览器流程：独立建卡、刷新恢复、邀请新建提交、移动端 390px 和桌面 1440/768px。
7. 运行类型检查、相关测试、全量测试、边界检查和生产构建；按项目配置对本次 TS/TSX 改动运行 Biome，配置仍缺失则如实报告。
8. 使用 design-taste 的 app lint 与真实浏览器 inspector 检查最终页面，阅读所有宽度截图并修正 FAIL；应用页不增加展示型入场动画。
