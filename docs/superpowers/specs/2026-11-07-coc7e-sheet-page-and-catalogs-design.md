# CoC 7e 人物卡整页化与官方数据表设计（2026-11-07）

## 意图

把「人物卡」从弹窗提升为独立页面，让建卡与查看都围绕规则书数据展开：职业参考表可选可查，本职技能由职业自动推导，HP/MP/SAN 等派生值实时计算，武器、护甲、法术提供官方预设，数值输入控件重新设计。

## 非目标

- 不改变规则系统抽象边界：职业、武器、护甲、法术数据与推导全部放在 `packages/shared/src/rules/coc7e/`，通用业务代码不硬编码规则判定。
- 不新增第二套规则公式；派生公式仍以 `derive.ts` 为唯一来源。
- 不迁移历史数据、不删除既有入团快照；旧卡缺少职业选择字段时按「自定义职业」回退。
- 不引入新依赖（虚拟列表、表格库等一律不加）。
- 不新增代码注释。

## 数据来源与生成

参考数据来自项目根目录的三份外部文件（未纳入 Git，仅本地）：

- `coc7th空白卡（粉）…xlsx`：`职业列表`（229 条职业：职业名、信用评级、职业属性公式、技能点、本职技能文本）、`本职技能`（技能 × 职业矩阵，★ 固定本职、☆/⊙ 二选一、☯ 社交技能、※ 多选、任意特长计数、专攻文本）、`武器列表 战斗`（104 条武器）、`防具表 载具表`（64 条护甲）。
- `COC7th守秘人规则书2002c.pdf`：核对职业、武器数值与派生公式。
- `克苏鲁神话魔法大典1.1.pdf`：法术预设条目（名称、消耗、施法用时、效果摘要），只取机械数值与自制的一句话摘要。

生成结果（提交进仓库）：

## 数据模型

```ts
interface Coc7eOccupationDefinition {
  id; name; era: "any" | "classic" | "modern";
  creditMin; creditMax;
  skillPointOptions;            // 属性公式，多个备选（如 教育×2＋敏捷×2 / 教育×2＋力量×2）
  fixedSkillKeys: string[];     // 具体技能键，或家族名（技艺/格斗/射击/科学/语言/驾驶/生存/学识）
  choiceGroups: { id; label; choose; pool: string[] }[];
  anySkillCount: number;        // 任意个人或时代特长数量
}
```

- 家族名表示「该家族任一专攻都算本职」；带括号的条目（`技艺(表演)`）只匹配该专攻。
- 人物卡 `occupation` 增加 `choiceSelections: Record<groupId, string[]>` 与 `freeSkillKeys: string[]`；`skillKeys` 保留为自定义职业的技能清单。
- 本职判定统一走 `coc7eIsOccupationalSkill(occupation, key)`，职业点/兴趣点账本据此归类，旧的 `skillKeys` 手动勾选行为在自定义职业下保持可用。

派生值全部来自 `deriveCoc7eSheetStats`：HP=⌊(CON+SIZ)/10⌋、MP=⌊POW/5⌋、初始 SAN=POW、SAN 上限=99−克苏鲁神话、MOV（STR/DEX/SIZ＋年龄＋修正）、伤害加成与体格、重伤阈值、职业点（职业公式）、兴趣点（INT×2）。年龄只给提示，不自动扣减属性。

## 界面

### 1. 数字步进器（`components/ui/number-stepper.tsx`）

通用组件：左右 `−`/`+` 按钮 + 中部数字输入，圆角胶囊、语义 token、禁用与边界态、长按连点、`aria-label` 由调用方传入。替换建卡与人物卡界面里的原生数字输入。

### 2. 职业参考表（`rules/coc7e/occupation-reference-table.tsx`）

建卡页「职业」区块内的整宽表格，也是独立可查的规则参考资料：

- 工具栏：搜索（职业名/本职技能）、时代过滤（全部/1920s/现代）、结果计数。
- 表格列：职业、信用评级、职业属性、技能点、本职技能（固定项实心 chip、可选组虚线 chip、任意特长计数 chip）。
- 选中行在表格下方展开详情卡：职业名、时代标签、信用范围、点数公式、按当前属性算出的职业点、本职技能推导结果（固定/可选/任意）、未完成的选择提示、`使用此职业` 主按钮。
- 数据量大（229 行），只渲染当前筛选结果，行内容保持轻量。

### 3. 本职技能推导

选择职业后：

- 固定本职：自动标记为「本职」，不需要玩家操作。
- 二选一/多选/社交技能组：以 chip 组呈现，`choose N`，超选禁用，已选计数可见；家族选项（科学/技艺/外语等）弹出专攻选择器，可选择目录内专攻或输入自定义专攻（写入 `customSkills`）。
- 任意特长：`N` 个空槽，用技能选择器填充，槽内技能计为职业技能。
- 进度条显示「职业点 X/Y、兴趣点 A/B、还有 N 项未选择」。

### 4. 武器/护甲/法术预设

- 武器选择器：按时代过滤的官方武器表，展示名称/技能/伤害/射程/装弹/故障值，选中即填入人物卡武器行；行内仍可编辑。护甲同表单槽位。
- 法术选择器：搜索法术名，选中填入法术行（名称/魔法值消耗/理智消耗/施法用时/效果摘要），效果文本可编辑。

### 5. 人物卡整页

- 新路由 `/pl/characters/$characterId` 与 `/gm/characters/$characterId`；人物库点击进入整页，不再使用弹窗。
- 页面结构：顶部（立绘、姓名、职业/时代、版本、保存与返回；GM 对玩家所有卡的数值只能走「永久修正」）；左列粘性派生值面板（HP/MP/SAN 上限、MOV、DB、体格、重伤阈值、职业点/兴趣点）；右侧分页签（属性与技能、装备与战斗、资产、法术与神话、资料与表情）。
- 建卡页与人物卡页共用同一套规则编辑器组件（`rules/coc7e/character-creation-editor.tsx`），差别只在提交按钮与初始数据。

## 验证

- shared：职业表完整性（信用范围、公式可解析、本职条目可解析到技能或家族）、推导（固定/家族/选择/任意特长归类到职业点）、武器表技能映射、护甲取值范围、法术表字段。
- server：Excel 导入的职业预设仍写入完整字段；既有契约测试不回归。
- client：数字步进器、职业参考表筛选与选择、本职推导交互、武器/法术选择器。
- 端到端：隔离数据库与浏览器检查建卡与整页人物卡。

## 实施结果（2026-11-07）

- 数据：229 条职业（信用/公式/固定本职/选择组/任意特长，全部由 `职业列表` 的原文推导并用两轮独立审计校对）、104 条武器、64 条护甲、469 条法术预设。
- 本职推导：`coc7eIsOccupationalSkill` 统一判定，固定/家族/选择组/任意特长全部计入职业点；自定义职业保留手工勾选。
- 界面：数字步进器替换原生数字输入；建卡页新增粘性实时派生条、可搜索职业参考表、本职推导选择器；武器/护甲/法术预设选择器；人物卡独立页 `/pl/characters/$characterId` 与 `/gm/characters/$characterId`。
- 验证：`bun run typecheck`、`bun run check:boundaries`、`bun run build:client` 通过；全量 595 项测试通过（shared 43 + server 296 + client 243 + theme-cli 2 + release 11）。本轮未重新执行认证浏览器截图检查。
