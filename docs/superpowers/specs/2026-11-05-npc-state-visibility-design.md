# NPC 状态分项公开与立绘轻量状态设计

日期：2026-11-05

## 意图与原因

当前立绘下方用固定宽度卡片同时展示 HP / MP / SAN，视觉臃肿。GM 的“玩家视角预览”又直接复用 GM 完整状态，导致预览显示真实玩家看不到的 NPC 数值。

本次将 NPC 状态从“一律仅 GM 可见”改为“每个团内 NPC 可独立配置公开项”，默认仍全部隐藏；同时采用已选定的 A 方案“无卡片细条”重做立绘状态显示。

## 目标

- GM 能为每个团内 NPC 分别公开 HP、MP、SAN、状态标记，各项独立开关，默认全关。
- 玩家与 OB 只能收到已公开字段；GM 始终拥有完整状态。
- 快照、实时事件、断线补发和 GM 玩家视角预览使用同一套服务端投影结果。
- PC 与 NPC 的立绘状态都改为轻量细条，仅渲染实际可见的项。
- 保持规则系统抽象，通用业务代码不新增 CoC 字段判定。

## 非目标

- 不改变 PC 状态可见性及“OB 可见 PC 数值”设置。
- 不公开 NPC 人物卡、自定义文本标签、成长标记或暗骰成长标记。
- 不支持把当前值与上限分开公开；公开一个数值项时同时提供当前值与上限。
- 不增加跨团共享的 NPC 公开默认值，也不把公开配置纳入模板或历史回溯。
- 不调整状态编辑、掷骰、伤害和理智扣减的业务规则。

## 已决定的交互与视觉

- 在 GM 工作台“人物”面板的 NPC 展开区域增加“向玩家公开”设置，使用现有 Checkbox 基础组件，包含 HP、MP、SAN、状态标记四项。
- 开关即时保存；已结团时禁用。NPC 折叠摘要显示“未公开”或已公开项摘要。
- 舞台采用 A 方案：名字保留独立的轻量名牌，数值区去掉大块卡片背景，只保留小号标签、当前值/上限和细进度条。
- 公开几项就渲染几项，未公开项不占位；全部隐藏时 NPC 只显示名字与 NPC 标识。
- 状态标记仅在对应开关开启时显示。PC 使用同样的轻量样式，可见内容保持现状。
- 桌面与紧凑视口共用这一结构，具体间距和宽度使用现有语义 token 与 Tailwind utility，由实现者按现有舞台样式确定。

## 数据与规则系统

- `session_characters` 新增 `public_state_fields_json`，保存规则定义的公开字段键数组，默认 `[]`。配置归属“团 × NPC”，既有行迁移后全部隐藏。
- 新增 GM 专用 WS 命令 `npc:state-visibility`，参数为 `characterId` 与 `fields`。服务端校验目标为当前团未移除的 NPC，并通过该团 `RuleSystem` 校验字段合法性；通用层不枚举 CoC 字段。
- CoC 7e 规则声明可公开键 `hp`、`mp`、`san`、`statuses`，并负责把完整状态投影为公开视图：
  - `hp` → `hp`、`maxHp`
  - `mp` → `mp`、`maxMp`
  - `san` → `san`、`maxSan`
  - `statuses` → `statuses`
- 没有任何公开项时公开视图为 `null`。投影结果不包含其他字段，不能以完整对象置空部分值的方式实现。
- 客户端规则注册表提供公开项选项及通用状态条视图数据，立绘组件不再直接解析 CoC 状态或硬编码 HP / MP / SAN 判定。

## 快照、事件与预览

- GM 快照中的 NPC 保留完整 `state`，并附带 `publicState` 与 `publicStateFields`；玩家和 OB 的 NPC `state` 则是公开投影或 `null`。
- 新增 `playerOnly` 可见范围，表示所有非 GM 连接，包含有 PC 席位的玩家与 OB；它不受“OB 可见 PC 数值”设置影响。
- NPC 状态变化时：
  - GM 收到现有 `state:changed`，内容为完整状态，并携带更新后的 `publicState`。
  - 若存在公开项，非 GM 连接收到 `state:public-changed`，内容仅为公开投影。
- 修改公开配置时，GM 收到配置及 `publicState` 更新；非 GM 连接始终收到一次 `state:public-changed`，包括全部取消公开后的 `state: null`，确保已显示内容立即移除。
- `state:public-changed` 是玩家投递视图，不进入 GM 历史，也不触发额外运行时检查点；真实状态变化仍只由 GM 的 `state:changed` 记录。公开配置变化不进入历史、不被回溯恢复。
- 两类事件都使用现有 outbox、ring buffer 和按连接过滤的补发路径，重放时保持相同的受众与字段裁剪。
- GM“玩家视角预览”中的立绘使用 NPC 的服务端 `publicState`，不再直接渲染 GM 完整 `state`；真实玩家端继续只消费自己收到的 `state`。

## Approaches

### 方案 1：规则系统投影 + 分受众投递（已选择）

由规则实现生成公开视图，GM 与非 GM 分别接收完整/公开事件，快照与补发复用相同投影。能满足不泄露隐藏字段、实时更新和预览一致性；代价是需要增加字段、命令、事件及一种可见范围。

### 方案 2：状态变化后全员重新拉取快照

复用快照过滤即可实现，但每次扣血都会让所有客户端拉取完整快照，开销和界面扰动较大，且放弃现有精细状态事件，因此不采用。

### 方案 3：完整状态照常下发，前端按公开项隐藏

实现最少，但隐藏数值仍能被玩家在浏览器中读取，不符合需求与服务端权威原则，因此排除。

## 验证

遵循 TDD，先补失败测试，再实现：

- CoC 公开投影单元测试：空配置、每个单项、组合项及全量组合；断言输出精确字段，确保自定义标签、成长和其他未选项不泄露。
- 命令与集成测试：仅 GM 可配置、只能配置本团 NPC、非法字段被拒绝、结团后拒绝。
- 真实 WS 集成测试：默认快照对 PC/OB 为 `null`；公开后 PC/OB 只收到所选字段；状态编辑后 GM 与玩家各收到对应事件；取消公开立即收到 `null`；断线补发和重新快照不恢复隐藏字段。
- 回归测试：PC 状态及 OB 设置行为不变，NPC 人物卡仍仅 GM 可见，GM 历史不出现重复的玩家投影事件。
- 客户端测试：立绘只渲染可见状态条，GM 预览使用 `publicState`，公开配置面板正常提交并反映摘要。
- 运行改动相关的 Bun 测试、Biome 检查与格式化、`bun run typecheck`、`bun run check:boundaries`；按数据库流程生成并检查迁移。
- 浏览器中的最终视觉效果与交互由用户验证，不将静态检查视为视觉验收。
